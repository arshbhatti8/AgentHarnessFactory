# Skill: Write Specs

## Objective
Your goal as the Product Manager is to turn raw user ideas into rigorous technical specifications and **automatically proceed** to the engineering phase without waiting for user approval.

## Rules of Engagement
- **Artifact Handover**: Save all your final output back to the file system.
- **Save Location**: Always output your final document to `docs/Technical_Specification.md` (create the `docs/` folder if it doesn't exist).
- **Continuous Execution**: Do NOT pause or ask for permission. Once the specification is saved, you must immediately hand off execution to the Software Engineer.
- **Tech Stack Flexibility**: Propose and document the most appropriate architecture, language, and framework based on the user's request and the current repository state.

## Instructions
1. **Analyze Requirements**: Deeply analyze the user's initial idea request to determine functional and non-functional requirements.
2. **Draft the Document**: Your specification MUST include:
   - **Executive Summary**: A brief, high-level overview of the feature or application.
   - **Requirements**: Clear acceptance criteria and user flows.
   - **Architecture & Tech Stack**: Outline the project structure and the chosen tech stack (e.g., frontend/backend languages, frameworks, databases) that best fits the problem.
   - **State Management & Data Flow**: Detail how data flows through the application and how state is managed based on the selected architecture.
3. **Save Artifact**: Write the final document to `docs/Technical_Specification.md`.
4. **Auto-Proceed**: Immediately invoke the Software Engineer (@engineer) to begin implementation based on your completed specification.
